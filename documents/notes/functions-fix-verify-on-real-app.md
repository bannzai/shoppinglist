# Firebase Functions の修正は単体テストで止めず、デプロイ後に実アプリで結果のログまで確かめる

PR #405 (メンバー削除と URL 抽出の不具合の修正) で、owner から「Jest が通っただけでは動作確認済みにしない。simulator と実アプリで確かめる」と指摘された。この 2 件はどちらも既存の単体テストでは検出できていなかった。

- URL 抽出: テストが `node:https` をすべてモックしており、Node.js 22 の autoSelectFamily で `lookup` が `all: true` で呼ばれる実際の挙動が隠れていた
- メンバー削除: トランザクションのモックが、Firestore の「すべての read を write より先に行う」制約を再現していなかった

**なぜ:** モックは実行環境の挙動 (Node.js のバージョンごとの DNS 解決、Firestore のトランザクションの制約) を再現しないことがあり、単体テストが通っても本番で失敗する。

**どう使う:**

- Functions を直したら、デプロイの後に実アプリで該当の操作を行う (デプロイを誰が行うか・検証の場所は `AGENTS.md` に従う)
- 画面のトーストやシートだけで判断せず、`flutter run` のログの `<関数名>.result: ...` (`lib/utils/functions/firebase_function.dart` の `debugPrint`) で戻り値を確かめる
- 複数ユーザーが要る操作は、開発者オプションの「デバッグユーザー作成」で 1 台で再現する
- 確認の後は、開発者オプションの「デバッグデータクリーンアップ」で作ったデータを消す
