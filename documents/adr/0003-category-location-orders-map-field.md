# 0003. カテゴリのロケーション別並び順をマップフィールドで管理

## Status

Accepted

## Context

異なる買い物場所（スーパー）では売り場の配置が異なるため、カテゴリの表示順序を買い物場所ごとに設定したい（Issue #73）。
現状 `GroupCategory` は単一の `order` フィールドのみで、全ての買い物場所で同じ順番で表示される。

ロケーション別順序の保存方法として以下の3案を検討した：

- **Option A**: `GroupCategory` ドキュメントに `Map<String, int> locationOrders` フィールドを追加（key = shoppingLocationID, value = 順序）
- **Option B**: 新サブコレクション `categoryLocationOrders` を作成し、ロケーション×カテゴリごとにドキュメントを持つ
- **Option C**: グループ直下にジャンクションコレクションを作成

## Decision

**Option A（マップフィールド埋め込み方式）** を採用する。

## Rationale

- **追加クエリ不要**: 既存の `categories` ストリームがそのまま使え、別コレクションへのクエリが不要
- **前例との一貫性**: `GroupCategoryKeyword` がドキュメント埋め込みで実装されており、同じパターンを踏襲
- **ドキュメントサイズ**: 買い物場所の数は現実的に数個〜十数個であり、マップのサイズがFirestoreの1MBドキュメント制限に到達することはない
- **変更量最小**: 新コレクション・エンティティの追加が不要で、エンティティへのフィールド追加のみで済む
- **後方互換性**: `@Default({})` により既存データは空マップとして扱われ、デフォルトの `order` にフォールバックする

## Consequences

- カテゴリドキュメントのサイズが買い物場所の数に応じて微増する（実用上問題なし）
- ロケーション別順序の取得に追加クエリは不要だが、全カテゴリのドキュメントを読み込む必要がある（現状と同じ）
- 買い物場所を削除した場合、各カテゴリの `locationOrders` から該当エントリを削除するクリーンアップが将来的に必要になる可能性がある
