# App Privacy / データセーフティの回答内容

App Store Connect の App Privacy と Google Play のデータセーフティは、どちらも API から設定できないため
Web UI で回答する。ここに実装から読み取った収集データをまとめ、回答が実態とずれないようにする。

- App Store Connect API: v4.4.1 の全 966 パスに data usage / privacy 関連のエンドポイントが無い
- 回答が未公開のままだと、審査提出が `STATE_ERROR.APP_DATA_USAGES_REQUIRED` で拒否される

## 収集しているデータと用途

| データ | 収集元 | 用途 | ユーザーに紐づくか | トラッキング |
|---|---|---|---|---|
| ユーザー ID | Firebase Auth（匿名 / Apple / Google サインイン） | アプリの機能（グループ共有の本人特定） | 紐づく | しない |
| メールアドレス | Apple / Google サインイン | アプリの機能（アカウント復元） | 紐づく | しない |
| ユーザーコンテンツ（買い物リスト・アイテム・カテゴリ・グループ名・表示名） | Firestore | アプリの機能 | 紐づく | しない |
| 写真 | `image_picker`（レシート・広告の読み取り） | アプリの機能（AI での品名抽出） | 紐づく | しない |
| 正確な位置情報 | `geolocator`（店舗のジオフェンス通知） | アプリの機能 | 紐づく | しない |
| 購入履歴 | RevenueCat / StoreKit | アプリの機能（プレミアム判定） | 紐づく | しない |
| デバイス ID（FCM トークン） | Firebase Messaging | アプリの機能（グループ更新のプッシュ通知） | 紐づく | しない |
| 使用状況データ（画面遷移・操作イベント） | Firebase Analytics | 分析 | 紐づく | しない |
| クラッシュデータ・診断データ | Firebase Crashlytics | アプリの機能（不具合の調査） | 紐づく | しない |

## トラッキングは「なし」

広告 SDK（AdMob）は撤去済みで、他社サービスへのデータ提供も行っていない。
`NSUserTrackingUsageDescription` / `SKAdNetworkItems` も Info.plist から削除している。

トラッキングありと申告すると ATT の実装が必要になり、実態とも合わない。

## App Store Connect での入力先

App Store Connect → アプリ → 「App のプライバシー」→「データ収集」を編集し、上表のデータ種別を選択する。
各データについて「App の機能」「分析」の用途を選び、「ユーザーに関連付けられる」を選ぶ。
トラッキングはすべて「いいえ」。回答後に「公開」まで行わないと審査提出できない。

## Google Play でのデータセーフティ

同じ内容を Play Console → ポリシー → アプリのコンテンツ → データセーフティ で回答する。
あわせて次のフォームも未回答だと production へ公開できない:

- コンテンツのレーティング
- 広告の有無（「広告を含まない」を選ぶ）
- ターゲット層と実際のコンテンツ
