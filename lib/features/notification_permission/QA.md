# notification_permission QA

プッシュ通知の OS 許可ダイアログの前に価値を説明するプリパーミッションダイアログ（`lib/features/notification_permission/pre_permission_dialog.dart`）。画面を持たず、グループ招待・参加の導線（`maybeRequestNotificationPermission` の呼び出し元 4 箇所）から表示される。ダイアログ自体の構成（「あとで」「通知を許可」の 2 ボタン）と各ボタン・背景タップの戻り値（false / true / null）は widget test `test/features/notification_permission/pre_permission_dialog_test.dart` で担保済み。本 QA は widget test で書けない「表示するかどうかの判定」（OS の通知許可状態と導線）を対象にする。

## 仕様チェックリスト

| ID | 期待挙動 | 対応項目 |
|----|---------|---------|
| S1 | 通知許可が未要求（iOS: notDetermined）の時だけ、招待・参加の導線でプリパーミッションダイアログを表示する | 未要求状態で招待導線から表示される |
| S2 | 「通知を許可」で OS の通知許可ダイアログへ進む | 「通知を許可」で OS ダイアログが出る |
| S3 | 「あとで」・背景タップでは OS ダイアログを消費せず、次の導線で再表示される | 「あとで」で OS ダイアログを消費しない |
| S4 | 許可・拒否が確定した後は何も表示しない | 確定後は表示されない |
| S5 | 招待する側 3 導線（リスト設定の「グループに招待」・グループ設定の「招待コードを発行」・グループ作成直後）と招待された側（参加成功直後）の 4 箇所から呼ばれる | 他の導線からも表示される |

## 1. 表示条件

- [ ] **未要求状態で招待導線から表示される**: 通知許可を一度も要求していない状態で、設定 → グループ管理 → グループ作成 → 招待コードダイアログを「閉じる」と、「通知を許可」「あとで」の 2 ボタンを持つプリパーミッションダイアログが表示される
  - 自動化: auto（maestro/flows/notification_pre_permission_test.yaml。通知許可が未要求のシミュレータでのみ通る。2 回目以降はダイアログが出ずタイムアウトするため、新規シミュレータ（sim-boot）か `xcrun simctl erase` 後に実行する）
- [ ] **「通知を許可」で OS ダイアログが出る**: プリパーミッションダイアログの「通知を許可」をタップすると OS の通知許可ダイアログ（「許可」「許可しない」）が表示され、「許可」でグループ管理画面に戻る
  - 自動化: auto（maestro/flows/notification_pre_permission_test.yaml）
- [ ] **「あとで」で OS ダイアログを消費しない**: 「あとで」または背景タップで閉じると OS ダイアログは出ず、別の導線（例: グループ設定の「招待コードを発行」を閉じた直後）でプリパーミッションダイアログが再び表示される
  - 自動化: manual（maestro flow は「通知を許可」で OS ダイアログを消費するため同じシミュレータで続けて確認できない。新規シミュレータで「あとで」→ 別導線の順に mobile-mcp で操作する）
- [ ] **確定後は表示されない**: OS ダイアログで許可または拒否を確定した後は、招待・参加のどの導線でもプリパーミッションダイアログが表示されない
  - 自動化: manual（上の maestro flow を通した直後のシミュレータで、グループ設定の「招待コードを発行」を閉じてもダイアログが出ないことを mobile-mcp で確認する）
