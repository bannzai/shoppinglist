# レビューコメント評価ガイド

レビューコメントを accept / reject / already-fixed に分類するための判断基準。

## accept する条件

以下のいずれかに該当する場合は accept:

### 明確な規約違反
- `.claude/rules/` または `documents/` に明記された規約に違反している
- 例: `{required}` がない、`ref.watch` をコールバックで使っている

### バグ・ロジックエラー
- null 安全性の問題
- 条件分岐の漏れ
- リソースリーク

### 型安全性・セキュリティ
- 不適切なキャスト
- 入力バリデーションの欠如

## reject する条件

以下のいずれかに該当する場合は reject:

### 誤検知
- コードを正しく読み取れていない指摘
- 実際には問題がないコードへの指摘

### 規約との矛盾
- プロジェクト規約と矛盾する指摘
- 例: 「フィールド名を短くすべき」→ 規約は省略禁止

### スタイルの好み・スコープ外
- 規約に規定がなく機能的に同等な書き方の提案
- PR の変更範囲外のコードへの指摘

### Gemini Code Assistant の典型的な誤検知パターン
- import 文の順序（dart format が管理）
- 存在する型や関数への「未定義」指摘
- Riverpod Generator のパターンに合致しているのに指摘
- freezed の生成コードに対する指摘

## already-fixed の判定

- 指摘箇所のコードが後続コミットで既に修正済み
- 指摘内容と現在のコードが一致しない

## 返信メッセージのガイドライン

- **accept**: 何を修正したかを簡潔に記述（例: 「修正しました。`ref.watch` → `ref.read` に変更」）
- **reject**: reject の理由を具体的に説明し、該当する規約やパターンがあれば引用
- **already-fixed**: 既に修正済みである旨を記述
